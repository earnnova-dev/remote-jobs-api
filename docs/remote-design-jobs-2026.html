Why a feed beats a job board for design roles

If you're a product, UX, or design engineer — or building a tool for one — a static job-board page goes stale the moment a listing closes. A feed doesn't. You can:

  • Pull GET /v1/jobs on a schedule and filter to design roles client-side, surfacing only new roles (dedupe on the stable id).
  • Filter by min_salary to skip roles that won't meet your target, or by source to bias toward a board you trust.
  • Rank by fit_score to surface the best-matching roles for a specific portfolio or role description.
  • Get salary where the board publishes it — currently 86 of 329 live roles carry a salary figure (26%), with a median of $90,000 and a top of $300,900.

That is a data-availability fact, not a gap in the feed: the feed reports exactly what each board exposes, and the salary filter works the moment a board does publish a figure.

Try it — no API key, no signup, one call

The free tier needs no authentication and allows 100 calls per month. Grab the current feed with a single request, then filter to design roles client-side:

curl "https://remote-jobs-api.tten.no/v1/jobs?limit=10"

Or pull the design slice into a script with the Python standard library — no dependencies:

import json, urllib.request, re

url = "https://remote-jobs-api.tten.no/v1/jobs?limit=500"
with urllib.request.urlopen(url) as r:
    data = json.load(r)

pat = re.compile(r"design|ux|\bui\b", re.I)
for job in data["jobs"]:
    if pat.search(job.get("title", "")):
        sal = job.get("salary_min") or "n/a"
        print(f"- {job['title']} | {job['company']} | {job.get('location')} | {sal}")

Useful parameters: skills (comma-separated), source (remotive, remoteok, jobicy, wwr, hn), limit, min_salary, and min_score (minimum fit_score).
