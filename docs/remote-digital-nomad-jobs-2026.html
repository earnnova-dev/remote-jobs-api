Why a feed beats a job board for nomad roles

If you’re running a location-independent career — or building a tool that surfaces nomad-friendly work — a static job-board page goes stale the moment a listing closes. A feed doesn’t. You can:

  • Pull GET /v1/jobs?limit=500 on a schedule and only surface new roles (dedupe on the stable id).
  • Filter for the location-independent / digital-nomad-tagged subset client-side, or by min_salary to skip roles that won’t meet your target, or by source to bias toward a board you trust.
  • Rank by fit_score to surface the best-matching nomad roles for a specific job description.
  • Get salary where the board publishes it — currently 106 of 328 live roles carry a salary figure (32%), and 6 of the 54 digital-nomad roles list a concrete figure (e.g. Delinea $300,000–$340,000; Pivotal Health $190,000–$220,000; Benchling $150,000–$200,000).

Try it — no API key, no signup, one call

The free tier needs no authentication and allows 100 calls per month. Grab the current feed with a single request:

curl "https://remote-jobs-api.tten.no/v1/jobs?limit=10"

Or pull it into a script with the Python standard library — no dependencies. The example below narrows to the digital-nomad subset client-side:

import json, urllib.request

url = "https://remote-jobs-api.tten.no/v1/jobs?limit=500"
with urllib.request.urlopen(url) as r:
    data = json.load(r)

def is_nomad(job):
    tags = " ".join(job.get("tags") or []).lower()
    blob = (job.get("title") or "").lower() + " " + (job.get("company") or "").lower()
    return "digital nomad" in tags or "digital nomad" in blob or "work from anywhere" in blob

for job in [j for j in data["jobs"] if is_nomad(j)][:10]:
    sal = job.get("salary") or "n/a"
    print(f"- {job['title']} | {job['company']} | {job.get('source')} | {sal}")

Useful parameters: skills (comma-separated), source (remotive, remoteok, jobicy, wwr, hn), limit, min_salary, and min_score (minimum fit_score).
