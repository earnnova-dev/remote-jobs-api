Why a feed beats a job board for frontend roles

If you're a frontend developer — or building a tool for one — a static job-board page goes stale the moment a listing closes. A feed doesn't. You can:

  • Pull GET /v1/jobs?skills=frontend on a schedule and only surface new roles (dedupe on the stable id).
  • Rank by the returned fit_score to put the strongest frontend-matching roles at the top.
  • Filter by min_salary to skip roles that won't meet your target, or by source to bias toward a board you trust.
  • Get salary where the board publishes it — currently 92 of 335 live roles carry a salary figure (27%), with a median minimum of $106,000 and a top of $300,900.

How the skill filter works — honestly

Passing skills=frontend does not hard-filter the feed to frontend-only jobs. It scores every posting for a frontend match (a title hit weighs more than a body/tag hit) and returns them best-first, with the top frontend-named roles leading the list. The full board is still available so you can see adjacent web, design, and full-stack roles. Combined with min_score you can keep only the strongest matches.

Salary data, honestly

Only 27% of the current 335-job snapshot publishes a salary (92 roles). Where a salary is present, the median minimum is $106,000 and the range runs up to $300,900 (a few boards list top-of-range far higher). Salary coverage varies by board — this is a data-availability fact, not a gap in the feed. The feed reports exactly what each board exposes.

Try it — no API key, no signup, one call

The free tier needs no authentication and allows 100 calls per month. Grab the current frontend-ranked remote roles with a single request:

curl "https://remote-jobs-api.tten.no/v1/jobs?skills=frontend&limit=10"

Or pull it into a script with the Python standard library — no dependencies:

import json, urllib.request

url = "https://remote-jobs-api.tten.no/v1/jobs?skills=frontend&limit=20"
with urllib.request.urlopen(url) as r:
    data = json.load(r)

for job in data["jobs"]:
    fit = job.get("fit_score") or 0
    sal = job.get("salary") or "n/a"
    print(f"- [{fit}] {job['title']} | {job['company']} | {job['location']} | {sal}")

Useful parameters: skills (comma-separated, e.g. frontend,react), source (remotive, remoteok, jobicy, wwr, hn), limit, min_salary, and min_score (minimum fit_score, requires skills).
