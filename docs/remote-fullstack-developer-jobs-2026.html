Why a feed beats a job board for full-stack roles

If you’re a full-stack developer — or building a tool for one — a static job-board page goes stale the moment a listing closes. A feed doesn’t. You can:

  • Pull GET /v1/jobs?limit=500 on a schedule and only surface new roles (dedupe on the stable id).
  • Filter by min_salary to skip roles that won’t meet your target, or by source to bias toward a board you trust.
  • Rank by fit_score to surface the best-matching full-stack roles for a specific job description.
  • Get salary where the board publishes it — currently 106 of 327 live roles carry a salary figure (32%), and the full-stack subset that lists one carries a median salary_min of $157,000 with a top band of $210,000.

Or pull it into a script with the Python standard library — no dependencies. The example below narrows to the full-stack subset client-side:

import json, urllib.request

url = "https://remote-jobs-api.tten.no/v1/jobs?limit=500"
with urllib.request.urlopen(url) as r:
    data = json.load(r)

def is_fullstack(job):
    t = (job.get("title") or "").lower()
    return any(k in t for k in ("full stack", "full-stack", "fullstack"))

for job in [j for j in data["jobs"] if is_fullstack(j)][:10]:
    sal = job.get("salary") or "n/a"
    print(f"- {job['title']} | {job['company']} | {job.get('source')} | {sal}")

Useful parameters: skills (comma-separated), source (remotive, remoteok, jobicy, wwr, hn), limit, min_salary, and min_score (minimum fit_score).
