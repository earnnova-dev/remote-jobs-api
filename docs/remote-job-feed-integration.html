Add a Live Remote Job Feed to Your Job Board or App

One JSON endpoint gives you live, normalized remote jobs from five boards. Here's exactly how to pull the feed on a schedule, filter it, rank it, and store the new jobs — copy-paste Python, no scraping.

Building a job board, a career page, an internal hiring tool, or a job-recommendation feature usually starts with the same painful problem: every job board exposes its data in a different shape. Remotive is a JSON API, We Work Remotely is JSON, RemoteOK is different again, Hacker News is a third schema. Maintaining one parser per board is slow and breaks the moment a site changes a field.

The faster path is to point your app at a single endpoint that already returns one clean, normalized schema — and just render what comes back. That's what the Remote Jobs API does: one endpoint, one schema, live data from five boards (Remotive, RemoteOK, Jobicy, We Work Remotely, Hacker News), no scraping on your side.

What you get: one GET /v1/jobs call returns up to 500 normalized job records with title, company, location, salary, source, tags, and an optional 0–100 fit_score when you pass skills. Free tier: 100 calls/month, all five boards.

The endpoint and its parameters

Everything lives on one route. The useful knobs are in the query string:

ParamNotes
skillsComma-separated keywords (e.g. python,backend,api). Adds a fit_score to every job and ranks the best matches first.
sourceRestrict to one board: remotive, remoteok, jobicy, wwr, or hn.
limit1–500 results (default 50).
min_score0–100. Keep only jobs above this fit score (needs skills).
min_salaryFilter by the parsed top-of-range salary; drops jobs with no parsed salary.
curl "https://remote-jobs-api.tten.no/v1/jobs?skills=python,backend,api&limit=3"

Notice the schema is identical no matter which board the job came from — that's the whole point. Your frontend never has to branch on source to render a card.

Pull the feed on a schedule (copy-paste)

The typical job-board pattern: on a cron (every 15–30 minutes is plenty), fetch the feed, find the jobs you don't already have, and insert them. Here's the minimal, dependency-light version using only the standard library:

import json, time, urllib.request, urllib.parse

BASE = "https://remote-jobs-api.tten.no/v1/jobs"

def fetch_feed(skills="python,backend", limit=100, min_score=None):
    params = {"skills": skills, "limit": limit}
    if min_score is not None:
        params["min_score"] = min_score
    url = BASE + "?" + urllib.parse.urlencode(params)
    with urllib.request.urlopen(url, timeout=30) as r:
        return json.load(r)["jobs"]

# jobs you already know about (your DB, a set of ids, etc.)
seen = load_existing_job_ids()          # <- your storage

new_jobs = []
for job in fetch_feed():
    if job["id"] in seen:
        continue
    new_jobs.append(job)
    save_job(job)                        # <- insert into your store

print(f"{len(new_jobs)} new remote jobs added")

Two details worth keeping:

  • Deduplicate on id + url. Job ids are stable per board, so a set of ids is enough to know "already seen". If you merge across boards and ids can collide, key on (source, id) or the job url.
  • Cache generated_at. The feed is a live snapshot. Store it so your "last updated" badge is honest and you can skip a fetch if it's too recent.

Filter and rank without writing parsers

Two things people normally scrape-and-parse by hand are already done server-side:

  • Salary filtering — pass min_salary and the API keeps only jobs whose parsed top-of-range salary clears it. No regex over a "$90k–$120k" string on your side.
  • Skill fit ranking — pass skills and every job gets a 0–100 fit_score, returned best-first. For a "jobs for you" widget, sort by fit_score (or just read the pre-sorted list) and show the top N.
# "Show the best Python backend roles at $120k+ top-of-range"
for job in fetch_feed(skills="python,backend", limit=50, min_score=60):
    if job.get("salary_max") and job["salary_max"] < 120000:
        continue
    print(job["fit_score"], job["title"], "-", job["company"])

Wire it into your UI

Because the schema is flat and uniform, a job card is one template:

{% for job in feed %}
  
    {{ job.title }} · {{ job.company }}
    {{ job.location }}
    {{ job.salary or "Salary not listed" }}
    {{ job.source }}
    {% if job.fit_score is defined %}Fit {{ job.fit_score }}{% endif %}
  
{% endfor %}

You can also ship a static "remote jobs" page that just renders the last fetched feed, refreshed by the same cron — no backend needed beyond the schedule.

When to self-host vs use the hosted API

The engine is open source and self-hostable (Helm chart included). Use the hosted endpoint if you just need a clean feed and don't want to run the board-scraping layer. Self-host the same engine when you need to stay on your own network, control rate limits, or extend the board set. Same schema either way, so your integration code doesn't change.
