Build a Remote Job Market Dashboard in ~40 Lines of Python

Live demand by board, salary distribution, and top skills — pulled from one free JSON endpoint and rendered as a report. No scraping, no paid data provider, no five fragile board parsers.

Most "job market intelligence" you'll find is either a static PDF that's stale by next month, or a paid enterprise dataset with a sales cycle. The fast, honest version is a live snapshot: what is the remote job market actually doing right now, across the major boards?

The Remote Jobs API already aggregates five boards (Remotive, RemoteOK, Jobicy, We Work Remotely, Hacker News) into one normalized schema — and exposes two endpoints that hand you the summary directly, so you never have to re-parse the raw listings to build a dashboard:

EndpointWhat it returnsUse for
GET /v1/snapshotLive job count, demand by source, salary distribution, top skillsThe "market pulse" header of your dashboard
GET /v1/salary-bandPer-skill salary bands (min / p25 / median / p75 / max)Salary-by-role tables
Both endpoints are keyless on the free tier — no token, no account. The numbers below were pulled live from the hosted API on 2026-10-01.

1. Pull the market pulse

One call gives you the whole top of the dashboard. No auth, no parameters:

import json, urllib.request

def snapshot():
    with urllib.request.urlopen(
        "https://remote-jobs-api.tten.no/v1/snapshot", timeout=15
    ) as r:
        return json.load(r)

s = snapshot()
print(s["count_live"], "live jobs across", len(s["sources"]), "boards")
print("by source:", s["demand_by_source"])
print("salary:", s["salary"]["coverage_pct"], "% covered, median",
      s["salary"]["median_min"], "p75", s["salary"]["p75_min"], "max", s["salary"]["max"])
print("top skills:", [(x["skill"], x["count"]) for x in s["top_skills"][:5]])

Against the live API on 2026-10-01 that prints:

2. Pull salary-by-skill bands

The second endpoint does the aggregation for you — a salary distribution per skill (a job's tag), sorted by how many listings carry a salary:

def salary_bands():
    with urllib.request.urlopen(
        "https://remote-jobs-api.tten.no/v1/salary-band", timeout=15
    ) as r:
        return json.load(r)

for s in salary_bands()["skills"][:4]:
    print(f"{s['skill']:<22} n={s['count_with_salary']:>3}  "
          f"med=${s['median']:,}  p75=${s['p75']:,}  max=${s['max']:,}")

Live output (2026-10-01):

full-time              n= 48  med=$135,000  p75=$165,000  max=$300,900
sales                  n= 13  med=$135,000  p75=$150,000  max=$300,000
software engineering   n= 10  med=$155,000  p75=$180,000  max=$300,900
exec                   n=  6  med=$150,000  p75=$175,000  max=$263,000
Honest caveat, carried on every data page here: salary coverage is ~24% of live jobs (only listings that publish a number), so the bands are a lower bound on the market, not a complete census. State the coverage number in your dashboard so readers know what they're looking at.

3. Render it as a report (self-contained HTML)

Combine the two calls into one refreshable report. This writes a single HTML file — no server, no build step, no chart library — that you can refresh on a schedule and post to a blog, an internal wiki, or a static site:

def market_report(path="market_report.html"):
    s = snapshot()
    sb = salary_bands()
    sal = s["salary"]
    rows = "".join(
        f"{x['skill']}{x['count']}"
        for x in s["top_skills"][:10]
    )
    bands = "".join(
        f"{x['skill']}{x['count_with_salary']}"
        f"${x['median']:,}${x['p75']:,}${x['max']:,}"
        for x in sb["skills"][:10]
    )
    html = f"""
    
Remote job market — {s['count_live']} live jobs

    
Median salary ${sal['median_min']:,} (p75 ${sal['p75_min']:,},
    max ${sal['max']:,}) across {sal['coverage_pct']}% of listings that publish one.

    
Demand by board

    {''.join(f'' for k,v in s['demand_by_source'].items())}
{k}{v}

    
Top skills

    {rows}
skilllistings

    
Salary bands by skill

    {bands}
skillnmedianp75max

    """
    open(path, "w").write(html)
    return path

print("wrote", market_report())

That's the whole dashboard: two GET calls, a small template, one file. Because the data is live, the report is never more than a refresh stale — the exact thing static PDFs can't do.

4. Schedule the refresh

Run it on a cron job, a GitHub Action, or a webhook. A GitHub Action that refreshes daily into a repo's docs/ (deployed by GitHub Pages) is a complete, free, always-current market dashboard:

# .github/workflows/market-report.yml
on:
  schedule:
    - cron: "0 6 * * *"      # daily at 06:00 UTC
  workflow_dispatch: {}
jobs:
  refresh:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: pip install nothing   # stdlib only, no deps
      - run: |
          python - <<'PY'
          # ... paste the market_report() function above ...
          PY
      - run: git diff --quiet || (git config user.email "ci@local"
          && git config user.name "market-bot"
          && git add -A && git commit -m "refresh market report" && git push)

Same engine is open source and self-hostable (Helm chart included) if you need the data on your own network — the two summary endpoints stay identical, so the dashboard code doesn't change.
