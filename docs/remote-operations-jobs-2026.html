Why a feed beats a job board for operations roles

If you're an operations professional — or building a hiring tool for one — a static job-board page goes stale the moment a listing closes, and operations titles are the most varied of any category. A feed doesn't. You can:

  • Pull GET /v1/jobs on a schedule and narrow to the operations subset client-side (match on title, company, and tags), surfacing only new roles (dedupe on the stable id).
  • Filter by min_salary to skip roles that won't meet your target, or by source to bias toward a board you trust.
  • Get salary where the board publishes it — currently 86 of 338 live roles carry a salary figure (25%), with a median of $120,000 and a top of $360,000 across the whole feed.
  • Catch the revenue-ops, supply-chain, and program-management titles that a "operations" keyword search on a single board would miss, because the full board is in one place.

How the operations filter works — honestly

There is no skills=operations hard filter, because operations is a category, not a skill — and many of these roles never use the word in the title. The feed has no operations tag to filter on either, so the honest approach is to pull the full feed and match the operations subset client-side against title, company, and tags (as the example below does). Combined with min_salary and source you can keep only the roles you actually care about.

Or pull it into a script with the Python standard library — no dependencies. The example below narrows to the operations subset client-side:

import json, urllib.request

url = "https://remote-jobs-api.tten.no/v1/jobs?limit=500"
with urllib.request.urlopen(url) as r:
    data = json.load(r)

OPS = ["operations", "revenue ops", "marketing ops", "supply chain",
       "logistics", "general manager", "program manager", "delivery manager"]
def is_ops(job):
    blob = " ".join([job.get("title") or "", job.get("company") or ""]
                    + (job.get("tags") or [])).lower()
    return any(w in blob for w in OPS)

for job in [j for j in data["jobs"] if is_ops(j)][:10]:
    sal = job.get("salary") or "n/a"
    print(f"- {job['title']} | {job['company']} | {job.get('source')} | {sal}")

Useful parameters: source (remotive, remoteok, jobicy, wwr, hn), limit, and min_salary (filters on the published floor salary). skills + min_score work the same as on the role pages.
