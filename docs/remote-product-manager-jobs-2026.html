Why a feed beats a job board for product roles

If you’re a product manager, product lead, or product owner — or building a tool for one — a static job-board page goes stale the moment a listing closes. A feed doesn’t. You can:

  • Pull GET /v1/jobs?limit=500 on a schedule and only surface new roles (dedupe on the stable id).
  • Filter by min_salary to skip roles that won’t meet your target, or by source to bias toward a board you trust.
  • Rank by fit_score to surface the best-matching product roles for a specific job description.
  • Get salary where the board publishes it — currently 107 of 328 live roles carry a salary figure (33%), and 7 of the 12 product roles list a concrete figure (e.g. Help Scout $263,000–$290,000; Amplitude up to $476,000).

Try it — no API key, no signup, one call

The free tier needs no authentication and allows 100 calls per month. Grab the current product roles with a single request:

curl "https://remote-jobs-api.tten.no/v1/jobs?limit=10"

Or pull it into a script with the Python standard library — no dependencies. The example below narrows to the product subset client-side:

import json, urllib.request

url = "https://remote-jobs-api.tten.no/v1/jobs?limit=500"
with urllib.request.urlopen(url) as r:
    data = json.load(r)

def is_product(job):
    t = (job.get("title") or "").lower()
    return any(k in t for k in ("product manager", "product lead",
                                "product owner", "head of product"))

for job in [j for j in data["jobs"] if is_product(j)][:10]:
    sal = job.get("salary") or "n/a"
    print(f"- {job['title']} | {job['company']} | {job.get('source')} | {sal}")

Useful parameters: skills (comma-separated), source (remotive, remoteok, jobicy, wwr, hn), limit, min_salary, and min_score (minimum fit_score).
