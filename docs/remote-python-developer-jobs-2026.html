Why a feed beats a job board for Python roles

If you're a Python developer — or building a tool for one — a static job-board page goes stale the moment a listing closes. A feed doesn't. You can:

  • Pull GET /v1/jobs?skills=python on a schedule and only surface new roles (dedupe on the stable id).
  • Filter by min_salary to skip roles that won't meet your target, or by source to bias toward a board you trust.
  • Rank by fit_score to surface the best-matching roles for a specific role description.
  • Get salary where the board publishes it — currently 88 of 323 live roles carry a salary figure (27%), with a median of $152,250 and a top of $500,000.

Try it — no API key, no signup, one call

The free tier needs no authentication and allows 100 calls per month. Grab the current remote Python roles with a single request:

curl "https://remote-jobs-api.tten.no/v1/jobs?skills=python&limit=10"

Or pull it into a script with the Python standard library — no dependencies:

import json, urllib.request

url = "https://remote-jobs-api.tten.no/v1/jobs?skills=python&limit=20"
with urllib.request.urlopen(url) as r:
    data = json.load(r)

for job in data["jobs"]:
    sal = job.get("salary") or "n/a"
    print(f"- {job['title']} | {job['company']} | {job['location']} | {sal}")

Useful parameters: skills (comma-separated), source (remotive, remoteok, jobicy, wwr, hn), limit, min_salary, and min_score (minimum fit_score).
